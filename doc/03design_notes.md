# 未決の設計論点

更新日: 2026-09-22

採用が決まっていない案と、判断に必要な論点だけを記載する。作業の一覧・保留状態は[作業リスト](04work_items.md)、現在の仕様は[設計書](01architecture_discussion.md)、確認済みの事実は[調査記録](02product_evaluation.md)を参照する。

## 1. 検索目的と不足情報

以下は作業A1の整理の出発点であり、新たな項目・テーブルの追加決定ではない。

| 検索例 | 現在できること | 残る論点 |
|---|---|---|
| 漫画・技術書・推理小説・ライトノベル・R18 | 保存済みの分類・紹介文・ジャンルを語句検索 | 分類未取得と非該当を区別する。単語への一致だけで種類・年齢区分を確定しない |
| 出版社 | 補完済みの出版社欄を部分一致で絞り込む | 書誌補完の不足による取りこぼし |
| 同じ著者 | 著者表示を含む語句検索で候補を探す | 同姓同名や原作・作画等をどこまで検索対象とするか。人物統合は前提にしない |
| 購入済みの未読続巻 | 未対応 | 読書状態、シリーズ、読む順序の根拠 |
| 全く読んでいないシリーズ | 未対応 | 所有巻すべての状態、不明を含む場合の扱い |
| Blender・3Dモデリング・Python | 書名・補完済み紹介文等の部分一致 | 書誌不足と検索語の不足を分ける。必要なら少数の目次等の補完を検討 |

検索結果への一致項目・補完状況の表示、著者・分類・シリーズを指定する検索は改善候補。シリーズURLによる絞り込みも候補だが、巻順・未読判定とは分ける。採用前に実際の利用例で必要性を確認する。

## 2. OR検索（保留）

既存の空白区切りAND検索に、繰り返し指定する`--any`で一つのORグループを加える案。未実装であり、以下は現行CLIでは使えない。

```powershell
pnpm dev library search "架空シリーズ" --any "1巻" --any "１巻"
```

- 条件は「基本語のAND AND anyのOR AND 出版社条件」。値はSQLパラメーターで渡す。
- anyの各値は空白を含め一つの部分一致文字列とする。1値200文字、最大20個、空値拒否を上限案とする。
- 同じ本が複数条件に一致しても重複させず、件数・ページ送りを維持する。
- 任意の式パーサー、複数ORグループ、NOTはこの案に含めない。全半角・同義語は利用者やAIが候補語を指定する。
- `1巻`の一致で作品の第1巻とは確定しない。架空データと保存済みサンプルで検証でき、Web再取得は不要。

## 3. 書誌補完の対象選択・失敗管理

未取得、取得失敗、取得成功だが項目欠損を区別する方法を検討する。現行missingFieldsは4項目の欠損一覧であり、試行履歴ではない。

対象の指定単位、処理件数上限、成功済みのスキップ、再取得を明示する方法、途中停止後の再開、失敗理由の記録範囲が未決。保存済みJSONの再利用を優先し、失敗で空の書誌文書を作らない。新しい履歴テーブルやCLI引数は必要性を整理してから決める。

## 4. 所有取得の範囲と更新

BOOK☆WALKERは先頭25冊の部分取得まで。通常一覧とアーカイブ・話購入・連携由来等の関係、終端・件数・重複を使った完了判定を検討する。公式CSVは調査候補であり、手動CSVを必須にする決定ではない。

新規購入の追加、既存情報の更新、途中再開をどこまで分けるかは未決。Kindleの現行全件取得も途中再開には未対応。差分取得可能とは断定せず、取得範囲外や一時的な欠落を削除根拠にしない。

次ストアで購入日欠損・ページなしAPI・定額利用権・複数アカウントが必要になった場合は、共通入力の変更を検討する。具体例なしに汎用化しない。CLI入口の登録表への統合も必要に応じて判断する。

## 5. 読書状態とシリーズ検索（保留）

Kindleで未着手と読書中を区別できるか、進捗・最終読書日時が取得できるかは未確認。BOOK☆WALKERの状態・進捗表示も、所有情報や書誌とは別の観測日時付き記録を候補とする。保存形式・状態の対応付けは未決。

- 既読表示がないことを未読・未着手とみなさず、進捗`--`も0に変換しない。
- 未読続巻は「同シリーズで読了した巻より後にある、明示的に未読の所有巻」を条件の候補とする。読む順序の根拠が必要。
- 全く読んでいないシリーズは「所有巻がすべて明示的に未読」を候補とする。不明を含む場合や1巻しか所有しない場合の扱いを決める。
- 読書状態の調査を、書誌補完を進めるための前提にしない。

## 6. AIとの接続（低優先度・保留）

用途別の引数付き検索関数をCLIで提供し、選び方・結果の読み方をSKILLへまとめる案。DB内のストアドプロシージャを実装する意味ではない。MCPも接続先の必要性に応じた選択肢として保留する。

SQL・入力検証・読み取り専用接続・件数制限はコード側、コマンド選択・検索語の広げ方・不足情報の説明はSKILL側が担当する案とする。対応AI環境、配置・配布方法、定型検索の範囲、MCPとの使い分けは未決。AIへの接続方法だけでは書誌や読書状態の不足を解消できない。

## 7. 外部書誌API・配布・運用

openBD等はISBNとの対応と収録項目・利用条件を確認してから採否を決める。所有取得の代わりにはならず、ストア商品と紙版・別版を安易に対応付けない。調査資料はdoc/02を参照する。

バックアップ・復元、履歴の保持、補完状況の表示、非プログラマー向けの導入・配布形式は未決。具体的な作業候補はdoc/04にまとめる。ゲーム版は別プロジェクト・別DBという決定を維持し、共通コードの切り出しは実際の要件が出てから判断する。
